# v3 에이전트 실험 계획 (E1~E6)

- 쓴 날: 2026-11-18 · 쓴 역할: 에이전트 설계 · 설계: [docs/v3/agents.md](../../docs/v3/agents.md) · 돌린 기록: [docs/v3/verification/agents.md](../../docs/v3/verification/agents.md)

## 0. 원칙

- **유료 API 0회.** 제품 코드는 `LLM_LIVE=false`, 키는 비워서 돌려요. LLM이 해야 하는 일(답 쓰기 흉내 · 채점 · 고객 흉내)은 Claude Code 하위 에이전트가 해요(구독 사용량에 들어가고 API 요금은 없음 [S27]).
- 같은 세트 · 같은 지표로 비교해요. 고르기는 dev로만, held-out은 고른 뒤 한 번만 봐요. 기준선 기록용으로 본 held-out은 결과 파일에 '봄'을 남겨요.
- 작은 세트는 건수와 Wilson 95% 구간을 같이 적어요. %만 쓰지 않아요.
- 숫자 · 근거 · 행동처럼 코드로 잴 수 있는 것은 코드로, 뜻 판단만 하위 에이전트로 채점해요.
- 실패는 실패로 적어요. 판정자는 사람이 아니라서 표본을 사람이 확인해요.

## 2. E1 라우팅 — 규칙 vs 분류기 vs 둘 다

- 묻는 것: 어느 담당으로 보낼지, 공종은 무엇인지, 언제 되물을지.
- 비교안
  1. 규칙만(낱말 · 정책 정규식)
  2. 분류기만(`intent_lr_v1` → v3 라벨로 다시 학습한 `intent_lr_v2`)
  3. 규칙 먼저 → 분류기
  4. 분류기(≥ 기준) → 규칙 → 되묻기 (지금 설계안)
  5. 4 + 보던 화면 동점 깨기
  6. (내려받기 승인 시) 작은 임베딩 분류기 — ADR-05
- 지표: 정확도 · macro-F1 · 라벨별 정밀도 · 재현율, 범위 밖 재현율 · 정밀도, 공종 슬롯 정확도(첫 공종 · 포함), 기준값별 '바로 받는 비율 / 받은 것의 정확도 / 되묻기 수' 곡선, 지연 p95.
- 채점: 코드(라벨 비교). 하위 에이전트 없음.
- 합격(held-out): macro-F1 ≥ 0.92, 바로 받은 것 정확도 ≥ 0.97 · 바로 받는 비율 ≥ 0.80, 다른 공종 → trade ≥ 0.95, 잡담 · 결제 → 범위 밖 재현율 ≥ 0.95.
- 상태: **기준선 돎**(2026-11-18, `e1_routing.py`). held-out 분류기 0.940 · 조합 0.970 · 다른 공종 7/7이 범위 밖으로 감 → 12공종 낱말 덮어쓰기로 v3 라벨 0.836 → 0.940.

## 3. E2 검색 — 바이그램 BM25 vs 변형 vs 하이브리드

- 비교안(모두 같은 말뭉치, `evaluation/rag/corpus.py`)
  1. 지금 서버 키워드 검색(바이그램 BM25 + 동의어 · 여러 검색어 RRF + 출처 등급 · 공정 무게) = 무료 모드
  2. 단순 바이그램 · 예시 질문 뺌 · 바이+트라이그램(무료 변형)
  3. 조각 머리말 붙이기(출처 > 장 > 절, 코드로, LLM 없음) [S13]
  4. 카드 열쇠 색인 더하기(카드 `keys`를 그 카드 근거 조각의 hints로)
  5. Kiwi 형태소 BM25 [S14] (모델 약 59MB 내려받기 — ADR-05)
  6. 키워드 + 의미 검색 RRF: 11-13에 만든 text-embedding-3-small 순위 사본(0원) = LLM 모드 근사
  7. (승인 시) 로컬 임베딩 KURE-v1 [S16] · 재순위 bge-reranker-v2-m3 [S15]
- 지표: hit@1 · hit@5(Wilson 구간) · recall@5 · MRR · nDCG@5, 공종별, '자료 없음' 질문을 '부족'으로 본 비율, 질문당 지연.
- 채점: 코드(`evaluation/rag/metrics.py`). 10공종 세트의 gold는 하위 에이전트가 판정(300세트와 같은 기준: 후보 = 여러 검색 위 12개 합집합, 번호 순으로 섞어 보여 줌).
- 합격(held-out): 무료 모드 hit@5 ≥ 0.75, LLM 모드 ≥ 0.80, 10공종 세트 hit@5 ≥ 0.70, '부족' 판단 ≥ 0.6(관문 정책과 합쳐서).
- 상태: **기준선 돎**. 무료 모드 held-out hit@5 0.697 · MRR 0.684(99문항), 의미 검색 사본 더하면 0.758. 예시 질문을 빼면 dev 0.665 → 0.539.

## 4. E3 답 만들기 — 카드 vs 추출식 vs 카드+조각 vs LLM 흉내

- 비교안
  - A 카드만(받아들이기 기준을 넘으면 카드, 아니면 '모름')
  - B 추출식만(검색 위 조각에서 문장 1~3개)
  - C 카드 → 추출식 → 모름 (무료 모드 설계안)
  - D LLM 모드 흉내: 하위 에이전트(`v3-answer-sim`)가 제품 LLM과 **같은 입력**(지시문 · 카드 · 조각 · 계산 결과 · 프로젝트 칸)만 받아 `Section` JSON을 씀. 그 뒤 제품 출력 검사(`guard.check` · 인용 확인)를 그대로 거침
  - E D + 카드 먼저(카드 점수가 높으면 LLM 안 부름)
- 지표(문항마다)
  - 코드: 지어낸 숫자 수(0이어야), 인용 정밀도(인용 조각이 보인 것인지 · 겹침), 금지 표현, 답한 비율, '모름'이 맞았는지(자료 없음 질문), 길이
  - 하위 에이전트 판정: 근거성(문장마다 supported · partial · unsupported, RAGAS faithfulness 정의 [S23]), 질문 핵심에 답했나(yes · partial · no), 기대 행동(`expect`) · 하면 안 되는 것(`must_not`), 해요체 · 읽기 쉬움
- 채점 절차: 5절.
- 합격(held-out): 근거성 ≥ 0.90, 인용 정밀도 ≥ 0.95, 지어낸 숫자 0, 답하면 안 되는 질문 통과 ≥ 0.95, 자료 없음 질문에서 '모름' ≥ 0.80, 무료 모드 답한 비율 ≥ 0.60.
- 상태: **사전 실험만**(`e3_card_proxy.py`, 예시 질문을 카드 열쇠로 흉내). 비슷함 + 검색 맞물림이 정밀도를 올림(기준 0.4: 0.470 → 0.679). 진짜 카드는 아직 없음.

## 5. 채점 절차 (하위 에이전트 판정)

1. 답 모으기: 비교안마다 같은 문항의 답을 만들고, 비교안 이름을 지운 무작위 id를 붙여요.
2. 판정자: `.claude/agents/v3-judge.md`(만들 것). 도구는 읽기만, 입력은 문항 · 보인 조각 · 답 하나(또는 둘)뿐. 다른 비교안 이름 · 기대 점수를 모르게 해요(따로 문맥 [S27]).
3. 루브릭: 1~5점 대신 **실패 유형마다 통과 / 실패** 이진(근거 없음 · 숫자 지어냄 · 범위 밖 처리 · 되묻기 누락 · 추천 · 하자 단정 · 핵심 빠짐).
4. 둘을 견줄 때(E4 · E5): A/B와 B/A 순서로 두 번 판정해요. 두 번 같은 쪽이면 승, 엇갈리면 비김 [S20].
5. 형식 편향 막기: 답을 같은 평문으로 바꿔 보여요(마크다운 · 제목 · 굵게 지움, 길이는 그대로) [S21].
6. 판정자 둘: 다른 하위 에이전트(다른 지시문 표현 · 다른 모델 설정이 가능하면)로 20%를 다시 판정해 일치율(κ)을 적어요. 한국어 판정은 언어 간 일치가 낮다는 보고가 있어 [S22] 사람 표본을 꼭 둬요.
7. 사람 표본: 실패 유형 3개(숫자 지어냄 · 범위 밖 처리 · 근거 없음)마다 30문항(통과 15 · 실패 15)을 리드 · 사용자가 라벨해, 판정자의 맞게 잡은 비율(TPR) · 맞게 통과시킨 비율(TNR)을 적어요.
8. 기록: `evaluation/v3/results/<실험>_<날짜>.json`에 문항별 판정 · 판정자 이름 · 지시문 판 · 비교안을 남겨요.

## 6. E4 단일 vs 다중 — 여러 공종 질문

- 묻는 것: 공종이 섞인 질문을 한 번에 답할지, 오케스트레이터가 나눠 담당에 보내고 합칠지.
- 비교안
  - 단일: 질문 전체로 한 번 검색 · 카드 하나(공종 슬롯 없음)
  - 다중: 나누기 → 공종 담당 → 공정 순서대로 합치기 + 겹침 문장
  - (LLM 흉내) 단일 LLM 한 번 vs 다중(담당마다 LLM)
- 지표: 조각 덮기(기대한 하위 질문을 모두 답했나, 코드 + 판정), 공정 순서가 계산 엔진 규칙과 맞나(코드), 공종 사이 모순(판정), 길이 · 호출 수 · 지연, 쌍대 비교 승률(순서 바꾸기).
- 합격: 다중이 조각 덮기에서 단일보다 낫고(≥ +0.15) 순서 위반 0. 아니면 단일을 기본으로 둬요.
- 상태: 대기(세트 `multi.jsonl` 필요).

## 7. E5 지시문 변형

- 대상: LLM 모드 지시문(가이드 · 공종 · 견적 설명 · 일정)과 무료 모드 정해 둔 글(모름 · 정책 · 실측 초안).
- 비교안: 판 v1 vs v2(한 번에 한 가지 차이: 카드 우선 문장 · 되묻기 조건 · 인용 규칙 · 길이 규칙).
- 방법: E3의 D(하위 에이전트 흉내)로 두 판의 답을 만들고 5절 쌍대 판정. 무료 모드 글은 고객 대변인 하위 에이전트가 쌍대로 읽기 쉬움을 판정.
- 합격: 새 판이 dev에서 승률 ≥ 0.6이고 새로 실패한 문항 0(있으면 이유를 적기). 그때만 held-out 한 번.
- 상태: 대기.

## 8. E6 사용자 흉내 대화

- 방법: 하위 에이전트(`v3-sim-user`)가 페르소나 · 목표 · 아는 것 · 말투를 받아 고객 역할을 해요. 상대는 **실제 무료 모드 코드**(`agent.v3.turn`, 스크립트가 한 턴씩 부름)예요. 흉내 고객은 매 턴 '목표까지 남은 것'을 적어요(목표 놓침 막기 [S26]).
- 끝: 목표 달성 · 12턴 · 같은 질문 3번 · 흉내 고객이 포기.
- 지표: 목표 달성률(τ-bench처럼 끝 상태 비교 — 예: 표준견적서 줄 풀이를 봤나, 초안 카드에서 보내기 버튼까지 갔나) [S25], 턴 수, 되묻기 반복, 잘못 간 담당, '모름' 뒤 다음 할 일로 이어졌나, pass^3(같은 목표 3번 모두 성공).
- 합격: 목표 달성률 ≥ 0.8, pass^3 ≥ 0.6, 되묻기 반복(같은 칸 2번 이상) 0.
- 상태: 대기(고객 대변인의 페르소나 · 시나리오 필요).
