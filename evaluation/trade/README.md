# 공정 담당(도배 · 목공) 평가

v2 상담(`/v2/ask`)의 공정 상담 역할은 질문 낱말로 공정 하나가 분명하면 그 공정 담당 지시문을 더한다. 공정은 코드가 고르고, LLM은 쓰지 않는다 (팀 C안의 공종 에이전트 하위 호출은 후속).
- 담당은 상담 지시문(`ask.PROMPT_VERSION["chat"]`)에 자기 지시문(`trade_dobae_v1` · `trade_mokgong_v1`)과 공정 설정(`app/agent/trades/`)을 더한다.
- 검색은 자기 공정 + 공통 자료를 먼저 본다.

## 파일
- `route.py`: 담당 고르기를 RAG 평가 질문(390문항)의 공정 표시로 잰다. 무료.
- `dobae.jsonl` · `mokgong.jsonl`: 담당별 답 평가 9문항씩. dev 6 · held-out 3이에요.
  - `expect`: 해야 할 행동. 조건 되묻기 · 주의점 · 자기 공정 근거 인용이에요.
  - `must_not`: 하면 안 되는 것.
  - `profile`: 질문마다 고객 상태를 정해요.
- 답 쓰기는 `evaluation/answer/run.py --set evaluation/trade/dobae.jsonl`로 해요. 유료이고, 18문항이면 약 $0.12예요.
  - 판정 기준은 `evaluation/answer/judge.md`에 `expect` · `must_not`을 더해요.

- 예전 낱말일 때 맞음은 dev 209, held-out 110이었어요.
- 고친 낱말
  - '방문'이 방문판매 · 실측 방문에 걸리던 것을 뺐어요.
  - 문짝 · 경첩 · 평탄화 · 단내림 · 커튼박스 · 목수 · 목재 · 퍼티를 더했어요.
- 일반 상담으로 간 질문은 대부분 공정 낱말이 없는 질문이에요. 예: '실측 뒤 금액이 올랐어요'.

드러난 문제
1. 조건 되묻기를 거의 하지 않는다(td01 · tm02). 지시문이 '조건을 모를 때만'이라 LLM이 모른다고 보지 않는다
2. 보여 준 자료를 덜 쓴다. 짧게 쓰라는 규칙 탓에 핵심만 말하고 근거 없는 결론 문장이 남는다
   - td04 결론 문장, tm02 '자료에는 없지만'(K255 · K909 · K911에 있음), tm05 LH 조각 대신 경험담 인용
3. 질문의 핵심을 빠뜨린다: td06 창문을 언제 여는지, td07 밀착 · 공간초배 차이
   - td06의 '2~3일'은 공사 기간은 계산 엔진 결과만 허용하는 숫자 검사 규칙대로 빠졌다
4. 근거성 0.5대는 예전 30문항(0.72~0.75)보다 낮지만, 질문 · 판정자가 달라 바로 견줄 수 없다
