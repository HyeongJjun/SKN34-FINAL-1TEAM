# 작업별 문서

[문서 목록](../README.md) · [기능 개발표](../feature-roadmap.md) · [작성 양식](../templates/task.md)

작업은 GitHub 이슈로 시작한다. 이슈에 책임 담당자, 목적, 변경 범위, 완료 조건을 적고 관련 기능 ID와 문서를 연결한다. 이 문서 목록에 담당자나 진행 상태를 따로 복사하지 않는다.

## 별도 문서를 만드는 경우

- 화면·API·DB처럼 여러 부분의 연결을 정해야 하는 작업
- 데이터 형식, 상태 전이, 에이전트 입출력처럼 다른 작업자가 따라야 하는 약속을 바꾸는 작업
- 선택한 설계의 이유나 재현 절차를 이슈 본문만으로 읽기 어려운 작업

간단한 오타·조건 수정은 이슈와 PR에 남기면 된다. 작업마다 빈 문서를 만들지는 않는다.

## 작성과 연결

1. [양식](../templates/task.md)을 복사해 `docs/tasks/<작업이름>.md`를 만든다. 파일명은 영어 소문자와 하이픈을 쓴다.
2. 이슈 본문에 문서 경로, 문서에 이슈 번호와 기능 ID를 적는다.
3. PR에 관련 이슈와 변경한 문서를 연결한다. 서로 다른 작업의 PR을 리뷰 편의로 합치지 않는다.
4. 변경한 동작을 기존 기준 문서에 반영하고 기능표의 코드·PR·검증 근거를 갱신한다.
5. 병합 뒤 이슈의 완료 조건을 확인하고 종료한다. 미래 기능이나 미검증 항목까지 함께 완료 처리하지 않는다.
