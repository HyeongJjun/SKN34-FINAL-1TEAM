# 리드 결정 — 제작 기준 (잠정, 사용자 확인 전)

- 날짜: 2026-11-18
- 역할별 조사에서 '사용자 확인 필요'로 올라온 것을 모았어요. 확인을 기다리는 동안에도 제작이 멈추지 않게, 리드가 잠정 기본값을 정했어요.
- 사용자가 다르게 정하면 바꿔요. 바꾸기 쉽게 상수 · 설정 한곳에 둬요.

## 0. 큰 원칙

1. **9판이 명세예요.**
   - 화면 · 흐름 · 글은 9판(`design/`)과 사용자가 고른 것을 따라요.
   - 보류 항목은 9판 그대로 둬요.
2. **대변인이 낸 새 기능 제안은 만들지 않아요.** 사용자 확인 목록에만 올려요.
   - 예: 하자 접수 기록, 계약 · 결제 안내, 관리자 2단계 인증
3. **바로 고치는 것**은 틀린 값 · 거짓 안내 · 접근성 · 보안 · 개인정보 안전에 해당하는 것이에요.
   - 예: 표준에 없는 줄을 % 비교에서 빼기, 보내지 않는 메일을 '보냈어요'라고 하지 않기, 평이 공급 평인지 전용 평인지 함께 묻기, 단추 읽는 이름, CSP 헤더
4. **글은 `copy-fixes.md`를 반영해요.** 다만 사용자 확인 Q1~Q5에 해당하는 것과 사용자가 직접 정한 글은 9판 그대로 둬요.

## 2. 제작 방식 (`plan-build.md`를 바꾼 점)

- **한 폴더(`wt-v3`)에서 맡는 파일을 나눠 동시에 만들어요.**
  - 묶음마다 worktree를 따로 두면 합칠 때 커밋이 필요해요. 커밋은 사용자가 말할 때만 해요.
- 프런트 출력 폴더는 `NEXT_DIST_DIR`로 나눠요. dev · build 모두 묶음마다 `.next-<묶음>`을 써요.
  - 리드가 `next.config.ts`에 `distDir` · `compress: false`를 넣어 뒀어요.
- 함께 보는 미리보기
  - API: `v3-api` 8030(DB `mitjip_v3`) · `.claude/run-api.sh`
  - 화면: `v3-web` 3030 · `.claude/run-web.sh`
  - 묶음이 자기 서버를 띄울 때는 `plan-build.md` 4장의 포트를 써요.
- 테스트: `bash .claude/run-tests.sh <묶음> tests/...`(묶음마다 DB · Redis를 따로 써요)
- 남의 파일이 고장 나 내 확인이 막히면 그 파일은 고치지 않아요. 리드에게 알리고 내 파일만으로 확인해요(예: typecheck 오류를 내 파일만 걸러 봐요).
- AI 칸 API(`/ai/*`)는 B5가 `backend/app/chat/`에서 직접 맡아요. B1a는 도구가 부를 읽기 함수만 내요.
