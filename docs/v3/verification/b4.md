### 1.1 글꼴 크기 — 리드 판단이 필요해요

- 지금(지시대로): `next/font/local` + `PretendardVariable.woff2` 한 파일 = **2,057,688바이트**. 굵기가 한 파일이라 400 · 600 · 700 · 800을 따로 받지 않고, 한 번 받으면 캐시돼요. 미리 받기를 끄고 `swap`이라 그동안은 대체 글꼴 줄(Pretendard → 시스템 글꼴 → Apple SD Gothic Neo · Noto Sans KR · 맑은 고딕)로 보여요.
- 다른 길: 패키지의 가변 다이나믹 서브셋 CSS(`pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`)를 `layout.tsx`에서 불러오면, 쪽 글자가 쓰는 조각만 받아 **어림 35만~37만 바이트**(위 표)예요. 대신 next/font의 대체 글꼴 크기 맞춤은 못 쓰고, Turbopack이 조각 woff2 92개를 옮기는지는 아직 확인 못 했어요.
- 폰 첫 방문 무게가 문제면 다른 길로 바꾸는 것을 권해요(바꿀 곳은 `app/layout.tsx` 한 곳).
- **2차에 리드 결정으로 다이나믹 서브셋으로 바꿨어요.** 실제로 받은 바이트는 5.1.

## 3. 남의 파일 · 함께 알아 둘 것

- B7 `frontend/proxy.ts`가 `X-Frame-Options: DENY` · `frame-ancestors 'none'`을 붙여서, 같은 주소 iframe으로 360 · 1280을 재는 방법은 막혀요(보안상 맞는 설정이에요). 그래서 화면 크기 흉내로 쟀어요.
- `next dev` · `next build`를 `NEXT_DIST_DIR=.next-b4`로 돌리면 Next가 `frontend/tsconfig.json`의 `include`에 `.next-b4/types/**/*.ts` · `.next-b4/dev/types/**/*.ts`를 더해요. 1차에는 돌린 뒤마다 되돌렸고, 2차부터는 리드 지시대로 두어요(여러 묶음이 동시에 돌아서 · 리드가 마지막에 정리).
- 타입 검사 · 린트 · 빌드에서 남의 파일 오류는 없었어요(1차 시각 기준). 2차 시각에는 B3 파일 오류가 있었어요(5.1).
- '저가형 · 기본형' 글이 남은 남의 파일(B2 · B3 · v2): `app/page.tsx` · `app/projects/[id]/standard/page.tsx` · `components/start/Wizard.tsx` · `components/project/RegradeButton.tsx` · `components/pro/profile/PriceSection.tsx` · `components/pro/inbox/text.ts` · `lib/mock/ask.ts` · `components/v2/*` · `public/v2/data.json`. `labels.ts`의 `DOBAE_GRADES` · `gradeLabel`을 쓰는 곳은 이미 '합지 · 실크'로 보여요.

### 5.3 B2b와 맞춘 이름(`components/site/LiveProvider.tsx`)

- 타입: `LiveEvent`(api.md 8장 `ready` · `msg` · `read` · `notif` · `state` · `resync`) · `LiveType` · `LiveSource = (emit) => 닫기`. B2b `stream.ts`가 이 타입을 가져다 쓰고 `export const openStream: LiveSource`를 내요 → `SOURCE = openStream`.
- 훅: `useLive()` → `{ unread, setUnread, subscribe, publish, connected }` · `useLiveEvent(type | "*", fn)` · `useLiveUnread(서버 값)`(머리 · 탭 바).
- B2 알림 화면은 읽음 처리 뒤 `useLive().setUnread(n)`. `stream.ts`의 `useStream`도 같은 연결 하나를 써서 섞어 써도 연결이 늘지 않아요.
- 보기용 머리처럼 떼어 둘 곳만 `<LiveProvider source={null}>`.

## 8. 5차(2026-11-19): 옆 AI 칸 첫 화면 입력 칸(B5가 찾음)

### 8.1 무엇을 고쳤나

- 찾은 것: 웹 1280×800 첫 화면(스크롤 0)에서 옆 칸 입력 칸 아래 끝이 858px, 창 밖으로 58px 나감.
- 원인(확인함): 칸은 본문 첫 묶음 윗줄(248px)에서 시작해요. 그런데 높이는 붙은 뒤 위치(156px)에 맞춘 628px로 고정돼 있었어요. 그래서 칸 아래 끝이 248 + 628 = 876px이었어요.
- 고친 것:
  - 칸 높이 = `clamp(320px, 100dvh − 칸이 시작하는 위치 − 16px, --mj-aside-h)`. 붙기 전에는 칸 아래 끝이 늘 창 아래 16px에 있고, 붙으면 N2 A 높이(최소 460)가 돼요.
  - 칸이 시작하는 위치는 `AsideSlot`이 스크롤 · 창 크기 · 내용 높이가 바뀔 때 재서 `--mj-aside-start`로 넘겨요. 붙는 자리보다 위로는 가지 않아요.
  - 칸 자신이 아니라 틀(WithAside)의 윗줄을 재요. 그래서 끝에서 칸이 밀려 올라가도 높이가 다시 바뀌지 않아요.
  - 스크립트 전 첫 그림은 흔한 머리(위 띠 + 108)로 짐작해요.
  - 새 토큰 `--mj-aside-start-min-h: 320px`(창이 아주 낮을 때 붙기 전 최소)을 더했어요. 바닥이 가장 큰 표준견적서(142px)에서도 목록이 96px 남아요.
- 고친 파일: `components/site/AsideSlot.tsx`, `components/site/frame.module.css`, `app/tokens.css`. B5 `components/ai/**`는 고치지 않았어요.
