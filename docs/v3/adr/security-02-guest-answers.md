# security-02 비회원이 넣은 답의 저장 위치 · 로그인 없는 계산

- 상태: 고름(9판 N1 A와 C02 '답은 이 기기에 저장돼요'를 따라요. 한도 숫자는 팀 확인)
- 날짜: 2026-11-18 · 쓴 역할: 보안 담당
- 관련 화면 · 이야기: C01 home0 · C02 info · C03 pyeong · C57 std_guest · C58 ai_guest · C59 join · C05 email · D10~D13, J1, 팀 확인 16(로그인 전 표준견적서)
- 관련 코드: `frontend/components/start/draft.ts`(지금 기기 저장) · `frontend/components/v2/store.ts` · `backend/app/v2/router.py`(계산 API는 모두 로그인 필요) · `backend/app/project/service.py` `create`

## 배경

- N1 A로 가입 전에도 표준견적서를 다 보여 줘요. 넣은 답과 표준견적서는 가입 전까지 이 기기에만 있고, 가입하면 내 공사로 옮겨요(C05 · C59).
- 지금 계산 API는 모두 로그인이 필요해서, 로그인 없는 계산 경로가 새로 생겨요. 그 경로의 한도와 저장 규칙을 정해야 해요(팀 확인 16).

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |
| A | 기기 localStorage(30일) + 저장하지 않는 계산 API | 가입 전 정보를 믿집이 모으지 않아요. 창을 닫아도 이어져 9판 문구와 맞아요. 지금 코드(`draft.ts`)와 같은 방식이에요 | 같은 기기의 다른 사람이나 XSS가 읽을 수 있어요 [2]. 그래서 식별 정보를 두면 안 돼요 [1] |
| B | sessionStorage | 탭을 닫으면 사라져요 [2] | 다시 열면 답이 없어져 '그대로 이어져요' 약속과 어긋나요 |
| C | 서버 임시 저장(비회원 쿠키 + TTL 7일) | 기기를 바꿔도 되고 서버가 검사해요 | 가입 전 정보를 믿집이 모아요(처리방침 · 보유 · 파기 대상). 봇이 저장소를 채울 수 있어요 |
| D | URL 쿼리에 답을 담음 | 공유가 쉬워요 | 예산 · 동네가 주소창 · 로그 · Referer로 새요(ASVS 14.2.1) [1] |

## 고른 것과 이유

- 고른 안: **A**, 아래 규칙과 함께
  1. 두는 것: 공종 · 범위(공간 · 면) · 주거 종류 · 시도/시군구/동 코드 · 면적(㎡ · 기준) · 사는 중/빈 집 · 벽지 · 예산 · 희망일 · 저장 시각 · 판 번호. 모두 `security.md` 3장 '낮음' 등급이에요.
  2. 두지 않는 것: 이름 · 이메일 · 휴대폰 · 단지 · 동 · 호 · 사진 · 계산된 금액(가입할 때 서버가 다시 계산해요).
  3. 키에 판 번호를 붙이고(예: `mj_start_draft_v5`), 저장한 지 30일이 지나면 읽지 않고 지워요.
  4. 읽을 때는 믿지 않고 스키마로 검사해요. 틀리면 버려요 [2].
  5. 로그인 없는 계산 API(이름은 개발자가 정해요)
     - 쿠키를 보지 않고, DB에 쓰지 않아요.
     - 본문은 16KB까지예요. 정해진 칸만 받아요(모르는 칸은 422).
     - 응답에 `Cache-Control: no-store`를 붙이고, 본문은 로그에 남기지 않아요.
     - 한도: IP 10분 30회 · 하루 300회. Redis가 멈추면 프로세스 안 한도로 대신해요 [3].
  6. 가입하면 화면이 답을 내 공사 만들기 API로 보내고, 서버가 다시 검사 · 계산해요. 성공하면 기기 저장을 지워요. 로그아웃하면 기기에 둔 공사 관련 값도 지워요(ASVS 14.3.1) [1].
  7. 화면에는 '답은 이 기기에 저장돼요' 옆에 '지우기'를 둬요.
  8. AI 칸은 로그인한 고객만 써요(C58). 비회원 답은 LLM으로 가지 않아요.
- 이유
  - ASVS 14.3.3은 민감 정보를 브라우저 저장소에 두지 말라고 해요. 그래서 등급을 나누고(14.1.1) '낮음'만 둬요 [1].
  - OWASP HTML5 치트시트: XSS가 저장소를 다 읽으니 민감 정보 · 세션 ID를 두지 말고, 읽은 값은 믿지 말라고 해요 [2].
  - 로그인 없는 API는 긁어 가기 · 남용 방어가 필요해요(ASVS 2.4.1) [3].
  - 2026.4 처리방침 작성지침은 기기 안에서만 처리하면 그 사실과 삭제 기준을 알리라고 권해요. 온디바이스 AI 항목이지만 같은 취지로 써요 [4].
  - XSS 자체를 줄이는 것은 CSP(OP-01)예요 [5].

## 검증

- 방법
  - T20(`security.md` 9장): 로그인 없이 계산해도 DB 행 수가 그대로인지, 모르는 칸(이름 · 번호)은 422인지, 가입하면 새 프로젝트가 생기고 기기 저장이 지워지는지 봐요.
  - T09: IP 한도를 넘으면 429와 Retry-After가 오는지 봐요.
  - 화면: 30일 지난 저장은 무시하는지, '지우기'가 되는지, 개발자 도구에서 저장 값에 식별 칸이 없는지 봐요.

## 다시 볼 조건

- 가입 전에 사진을 받게 되면 다시 봐요(사진은 기기 저장소에 두지 않아요).

- 법무가 처리방침 의견을 주면 다시 봐요.
