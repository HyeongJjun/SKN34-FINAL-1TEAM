# agent-01 에이전트 구조: 코드 관문 + 담당 바로 넘기기 + 복합만 오케스트레이터

- 상태: 고름 (실측 일정 초안을 일정 에이전트가 맡는 부분은 사용자 확인 필요)
- 날짜: 2026-11-18 · 쓴 역할: 에이전트 설계
- 관련 화면 · 이야기: C09 ai · D01 d_std · D03 d_visit · D08 d_req · C58 ai_guest, J1 처음 고객 · J3 업체 담기 · J5 실측 일정 · 관련 코드: `backend/app/agent/*`, `backend/app/v2/ask*.py`, 설계 [agents.md](../agents.md) 2~8절

## 배경

v3 에이전트는 12공종 + 공통 질문을 넓게 덮고, 키 없는 무료 모드가 기본이어야 해요. 지금 v2는 LLM 하나(`chat_v3`)가 가이드 · 공정 상담을 같이 하고, `LLM_LIVE=false`면 "지금은 AI 답변을 쓸 수 없어요"만 돌려줘요. 여러 에이전트가 어떻게 나눠 일할지를 먼저 정해야 지식 · 평가 · 화면 일이 갈라져 진행돼요.

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |

| B 코드 관문 + 담당 바로 넘기기 + 복합만 오케스트레이터(깊이 1) | 관문(규칙 + 학습 분류기)이 담당을 고르고 담당이 직접 답함. 복합 · 여러 공종만 오케스트레이터가 담당을 도구로 불러 합침 | LLM 없이 그대로 돌아요. 흐름이 예측 가능하고 토큰이 적어요. 담당마다 따로 평가할 수 있어요 | 나누기 · 합치기 규칙을 코드로 만들어야 해요. 관문이 틀리면 엉뚱한 담당이 답해요 |
| C LLM 감독자 중심 | 매 턴 감독 LLM이 담당을 부르고 답을 다시 써서 말함 | 유연해요 | 무료 모드가 안 돼요. 다시 쓰며 생기는 번역 손실 [4], 토큰 약 15배 [2], 순차 과제에서 손해 [6] |
| D 담당끼리 넘기기(swarm) | 담당이 다른 담당에게 직접 넘김 | 감독자보다 조금 나았다는 측정 [4] | 넘김 경로를 예측 · 시험하기 어려워요. 단계 반복 · 종료 못 함 같은 실패가 흔해요 [5] |

## 고른 것과 이유

- 고른 안: **B**
- 이유
  1. 예측 가능해야 하는 일은 정해진 코드 경로로, 가장 단순한 것부터 [1]. 코드 오케스트레이션이 속도 · 비용 · 성능을 더 예측 가능하게 해요 [3].
  2. 믿집 대화는 대부분 '한 의도 · 순차 질의응답'이에요. 다중 구조는 나눌 수 있는 과제에서 득이지만 순차 과제에서 최대 −70%였고 [6], 문맥을 같이 써야 하는 일에는 맞지 않아요 [2]. 그래서 단일 의도는 오케스트레이터를 거치지 않아요.
  3. 복합일 때 하위 답을 다시 쓰지 않고 그대로 넘기면 감독자 구조가 약 50% 나아졌어요 [4]. 오케스트레이터는 순서 · 겹침 문장만 더해요.
  4. 실패 유형 1위가 단계 반복(15.7%)과 종료 조건 모름(12.4%)이고, 상위 목표 검증이 가장 효과가 컸어요 [5] → 호출 상한 · 같은 호출 금지 · 출력 검사를 코드로 둬요.
  5. 관문은 이미 측정했어요: 학습 분류기 held-out 정확도 0.940, 분류기(≥0.7) → 규칙 조합 0.970 (verification/agents.md 표 1). 불확실할 때만 다음 단계로 넘기는 계단식 [7]과 후보 묶음 되묻기 [8]를 따라요.
  6. 무료 모드가 기본이라 LLM 없이도 같은 구조가 돌아야 해요. B만 그래요.
- 다섯 에이전트(오케스트레이터 · 가이드 · 공종 · 견적 설명 · 일정)를 유지하고, 실측 일정 AI 초안은 일정 에이전트가 맡아요. 9판 팀 확인 항목('AI 실측 일정 초안을 맡을 에이전트')이라 **사용자 확인 필요**예요.

## 검증

- 방법: E1(관문 정확도 · 기준값 곡선), E4(여러 공종 질문 단일 vs 다중), E6(흉내 고객 대화 목표 달성).
- 결과
  - E1 기준선(2026-11-18): held-out 분류기 0.940 · macro-F1 0.944, 조합 0.970. 다른 공종 7/7이 범위 밖으로 감 → 12공종 낱말 덮어쓰기로 v3 라벨 0.836 → 0.940.
  - E4 · E6: 검증 대기(세트 · 페르소나 필요).

## 다시 볼 조건

- E4에서 다중이 단일보다 조각 덮기 +0.15를 못 넘으면 오케스트레이터를 줄여요.
- 관문 오분류가 held-out에서 5%를 넘으면 관문을 다시 봐요.
- LLM 모드가 기본이 되고 복합 질문이 30%를 넘으면 C(감독자)를 다시 견줘요.
