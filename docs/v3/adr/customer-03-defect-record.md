# customer-03 공사 끝 확인 점검 목록 · 하자 접수 기록

- 상태: 사용자 확인 필요
- 날짜: 2026-11-18 · 쓴 역할: 고객 대변인
- 관련 화면 · 이야기: C38 done_ok · C39 review · C63 project_log · V13 v_done · V23 v_job, J7 · J22 · J24 · 관련 코드: `backend/app/schedule`(deals checking → fixing → done, `deal_events`)
- 관련 점검: `research/customer.md` F16 · F30 · F31 · F34

## 배경

- 피해구제 신청 1위는 하자보수 불만(56.9%)이고 합의는 35.8%예요. 합의가 안 된 이유는 업체가 하자 기준을 혼자 주장 · 보수 방법이 다름 · 연락 끊김이에요 [1].
- 하자담보책임 미이행 행정처분은 5년간 시정명령 2건뿐이라, 고객이 스스로 증거를 챙겨야 해요 [4]. 소비자원은 시공 전후 사진 등 입증자료를 권해요 [1][5].
- 9판 '공사 끝 확인'(C38)에는 무엇을 볼지 안내가 없어요. '고칠 곳 있어요' · '하자 접수'는 채팅 글로만 가서 기록 탭(C63)에 사건으로 남지 않아요.
- 끝 확인을 안 하면 7일 뒤 자동으로 끝나요(D24 A). 바쁘거나 앱을 자주 안 여는 고객은 확인 없이 끝나요.

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |
| A | 9판 그대로: 안내 없음, 하자는 채팅 글 | 만들 것이 없어요 | 분쟁 때 증거가 채팅에 흩어지고, 무엇을 볼지 몰라 너무 일찍 · 늦게 판단해요 |
| B | C38에 '끝 확인 전에 볼 것' 정적 목록(5줄 · 접기 · 숫자 없음). '고칠 곳 있어요' · '하자 접수'는 사진 · 곳 · 한 줄을 받는 카드로 채팅에 가고, 같은 일이 기록 탭(`deal_events`)에도 남아요 | 증거가 한곳에 모여요. 이미 있는 상태 전이(checking → fixing)와 맞고, 업체도 공사 한 건(V23)에서 같은 기록을 봐요 | 카드 하나 · 사건 종류 하나가 늘어요. 업체 답 기한을 둘지 정해야 해요 |
| C | B + 하자 판정 · 보상 기준 안내 | 고객이 판단하기 쉬워요 | 믿집이 하자를 판정하면 법률 판단처럼 보여요 [내1] |

## 고른 것과 이유

- 고른 안: **B**(사용자 확인 필요)
- 이유
  - 피해와 합의 실패의 중심이 하자 기준 다툼 · 연락 끊김이에요 [1]. 날짜 · 사진이 든 기록이 그 다툼을 줄여요 [1][5].
  - 상태 전이(checking → fixing → done)와 기록 탭(I2 A)이 이미 있어서 사건 종류 하나를 더하는 정도예요.
  - 판정은 하지 않아요. 목록은 '볼 곳'만, 하자 카드는 '사실'만 남겨요 [내1].
- 함께 정할 것
  - 자동으로 끝난 공사도 리뷰 · 하자 접수를 할 수 있게 해요(F16, 리뷰 규칙은 C49에 적어요).
  - 하자 접수 뒤 업체 답 기한(예: 접수 + 48시간)은 업체 대변인과 정해요. 이 ADR에서는 정하지 않아요.
- 점검 목록 초안(숫자 없음 · 판정 없음, 데이터 수집 담당이 시방서로 확인해요)
  1. 이음매가 벌어지거나 겹친 곳이 있어요?
  2. 모서리 · 창틀 · 문틀 끝이 들떴어요?
  3. 콘센트 · 스위치 둘레가 깔끔해요?
  4. 천장에 들뜬 곳이 있어요?
  5. 남은 벽지를 어디에 두었는지 알아요?
  - 끝줄: '젖어서 생긴 울음은 마르면서 줄 수 있어요. 남으면 사진을 찍어 접수해요.' — 근거가 D 등급 정리본이라 확인 전에는 넣지 않아요 [내1].
