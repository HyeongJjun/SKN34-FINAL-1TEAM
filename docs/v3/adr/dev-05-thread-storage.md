# dev-05 고객-업체 채팅 저장 · 연락처: `thread` 표에 직접 저장, 번호는 가리지 않고 주의 줄만

- 상태: 고름 (보관 기간은 사용자 확인 필요 — 팀 확인 7)
- 날짜: 2026-11-18 · 쓴 역할: 개발자
- 관련 화면 · 이야기: C23~C31 · C53 · C62 · D05 · V09 · V19 · V20, J8 · J17 · J20, 9판 D05 A · I7 B · D28(보류), 팀 확인 3 · 7 · 11 · 관련 코드: 새 `backend/app/thread/`, `backend/app/account/service.py`(탈퇴)

## 배경

실측이 확정되면 그 공사 · 그 업체 사이 대화가 열려요(UC-CHT-01). 코드 이름 `chat`은 AI 대화가 이미 쓰고 있어요(팀 확인 3). 9판 결정: 동 · 호 · 연락처는 고객이 채팅에 글로 직접 보내고(+ 메뉴의 '주소와 번호' 뺌), 업체는 구 · 동까지만 봐요. 번호는 가리지 않고 믿집 밖 거래를 권하는 글에만 고객 화면에 주의 줄 한 줄(D05 A). 탈퇴해도 이미 보낸 글은 그 업체 채팅에 남아요(C53).

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |
| A | 우리 DB에 `threads` · `thread_messages`(대화마다 seq) · `thread_reads`, 글마다 `client_key`로 한 번만 | 신고 · 기록 · 권한을 한곳에서 · 유료 서비스 없음 | 보관 · 파기 규칙을 우리가 정해야 해요 |
| B | 외부 채팅 서비스(SDK) | 읽음 · 푸시가 들어 있어요 | 유료 · 개인정보가 밖으로 · 신고 근거를 따로 옮겨야 해요 |
| C | 글은 Redis에만 | 빠름 | Redis는 지워져도 되는 것만 둬요. 다툼 근거가 사라져요 |
| D | 번호 · 주소를 서버가 가림(UC-CHT-03 A1) | 밖 거래 줄어듦 | 9판 D05 A(가리지 않음)와 달라요. 고객이 직접 보내는 동 · 호까지 가려져요 |

## 고른 것과 이유

- 고른 안: **A** + 코드 이름 `thread`(화면 말 '채팅'). 가림은 하지 않고(D05 A) 주의 줄만 규칙으로 붙여요.
- 이유
  - 신고(A02)는 '신고된 메시지'를 데이터로 보여 주고 기록해야 해서 원본이 우리 DB에 있어야 해요. 실시간은 dev-02(줄기에는 id만).
  - 같은 글이 두 번 저장되지 않게 브라우저가 만든 `client_key`를 (대화, 보낸 사람, 키) UNIQUE로 막아요(9판 dup 규칙 '채팅 글', S25).
  - 대화마다 `seq`를 대화 행 잠금 아래 하나씩 올려서 같은 대화의 글은 늘 순서대로 보이고, 빠진 것은 `after_seq`로 채워요.
  - 주의 줄(D05 A): 업체가 보낸 글이 '현금 · 계좌 · 입금 · 따로 계약 · 직거래' 같은 규칙 낱말에 걸리면 `warn = 'offsite'`를 저장하고 고객 화면에만 한 줄을 붙여요. 규칙 목록 · 문구는 B7 · UX 글 점검과 정해요. AI를 부르지 않아요(유료 0).
  - 업체 화면에는 고객 이름 대신 '상계동 고객'(동 + 고객)을, 고객 화면에는 업체 상호를 보여요. 이 이름표는 만들 때 사본으로 둬서 탈퇴 뒤에도 남아요.
  - I7 B(동 · 호를 안 보냈으면 전날 알림에 한 줄): 고객 글이 '○○동 ○○호' 꼴 규칙에 걸리면 `threads.address_sent_at`을 찍고, 전날 알림 일이 이 값을 봐요.

## 사용자 확인 필요

- **보관 기간(팀 확인 7)**: 탈퇴 · 다른 업체 확정 뒤 채팅 글을 업체가 얼마나 볼지 정해지지 않았어요. 개인정보보호법 제17조②(받는 쪽 보유 기간 알림) · 제21조(목적을 이루면 파기)와 부딪혀요. 설계는 `THREAD_RETENTION_DAYS`(기본: 비움 = 지우지 않음)와 닫힌 대화의 글 본문을 지우는 일(`thread_redact`)을 넣어 두고, 법무가 정한 날수만 넣으면 돌게 해요.
- 탈퇴(C53): 대화를 '닫힘'으로 바꾸고 고객 칸을 비워요(글 · 이름표는 남김). 지금 탈퇴는 사용자 행을 지워 이어진 행을 모두 지우므로, `threads`는 프로젝트 · 사용자에 `ON DELETE SET NULL`로 걸어요.

## 정한 세부

- 대화 하나 = (프로젝트, 업체). 실측이 처음 확정될 때 만들고 시스템 카드 '실측 12.15(화) 오전으로 정해졌어요'를 넣어요.
- 읽기만 되는 때: 다른 업체로 확정(견적서 닫힘) · 실측 취소 · 업체 못 받아요 뒤 · 고객이 차단 · 관리자가 쓰기 막기. 확정 업체 대화는 공사가 끝난 뒤에도 열려 있어요(하자 접수, C38).
- 사진: `POST /files`(kind `chat_photo`, 위치 정보 지움) 뒤 글에 붙여요. 파일은 대화 두 사람만 열어요.
- 차단(C31): 고객이 업체를 차단하면 그 대화는 업체 쪽 쓰기가 막혀요. 신고 · 차단 때 채팅 모양은 D28 보류라 8판 그대로(한 줄)예요.

## 검증

- 방법: pytest(B1b) — 같은 `client_key` 두 번 → 글 1개 · 두 번째는 같은 글을 돌려줌, 두 연결 동시 보내기 → seq 1 · 2 빈틈 없음, 남의 대화 글 읽기 404, 읽기만 되는 대화에 쓰기 409, 주의 줄 규칙 낱말 표, 탈퇴 뒤 업체가 글을 보고 고객 칸이 빈 것, 업체 응답에 고객 이름 · 휴대폰이 없는 것.
