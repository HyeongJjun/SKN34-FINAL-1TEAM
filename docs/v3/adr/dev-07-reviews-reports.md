# dev-07 리뷰 · 답글 · 신고: 공사 확정 한 건에 리뷰 하나, 신고는 한 표에 종류로

- 상태: 고름 (탈퇴한 고객 리뷰 처리는 사용자 확인 필요)
- 날짜: 2026-11-18 · 쓴 역할: 개발자
- 관련 화면 · 이야기: C39 · C48 · C49 · V24 · V25 · C31 · A02 · A03 · V18 · A01, J4 · J13 · J22 · J23, 9판 I4 A · D26 A · 팀 확인 8 · 9 · 관련 코드: 새 `backend/app/review/` · `backend/app/report/`, `backend/app/vendor/`, `backend/app/account/`(관리자 회원)

## 배경

공사 끝을 확인한 고객만 리뷰를 쓰고(별점 · 칩 4개 · 글 · 사진), 업체는 리뷰마다 답글 하나를 달고 고칠 수 있어요(I4 A). 고객이 고치면 '수정됨'이 붙어요. 전자상거래법 제21조의4(2026.7.21 시행)는 작성 권한 · 게시 기간 · 등급 기준 · 삭제 기준과 이의 제기 절차를 공개하게 해요(S34, 팀 확인 8). 신고는 채팅 · 업체 · 링크 세 가지를 관리자가 한곳에서 처리하고 기록해요(A02). 처리: 경고 · 채팅 쓰기 막기 · 업체 기능 멈추기(새 요청만, 사기 · 밖 거래면 진행 중인 건도 닫음, D26 A).

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |
| A | `reviews`(deal 1:1 UNIQUE) · `review_replies`(리뷰 1:1) · `review_photos`, 숨김은 상태 + 사유 코드. 신고는 `reports` 한 표(kind = chat · vendor · link) + 신고 때 글 사본, 관리자 처리는 `admin_actions`에 쌓음 | 법이 묻는 '삭제 기준 · 이의 제기'를 코드 · 기록으로 보여 줄 수 있어요 · 표가 적어요 | 신고 종류마다 대상 칸이 비는 조합을 CHECK로 지켜요 |
| B | 리뷰를 별점만(글 없음) | 단순 | 9판 C39 · V24와 달라요 |
| C | 신고 종류마다 표 따로 | 칸이 깔끔 | 관리자 목록(전체 · 채팅 · 업체 · 링크)을 합쳐 읽어야 해요 |
| D | 외부 리뷰 서비스 | 리뷰 관리 기능 | 유료 · '믿집에서 공사를 끝낸 고객만' 확인이 어려워요 |

## 고른 것과 이유

- 고른 안: **A**.
- 이유
  - '공사마다 한 번'(C49)을 `reviews.deal_id` UNIQUE로 DB가 지켜요. 쓸 수 있는지는 `deals.status = 'done'` + 작성자 = 그 공사 고객(service)으로 봐요.
  - 답글 하나(I4)는 `review_replies`의 기본 키 = 리뷰 id로 지켜요. 고치면 `edited_at`, 처음 달 때 고객에게 알림.
  - 삭제 · 숨김은 공개한 기준(욕설 · 개인정보 · 공사와 상관없음 · 대가를 받고 씀)에 맞는 사유 코드가 있을 때만 관리자가 하고, `admin_actions`에 남겨요. 이의 제기는 신고(`reports`)로 받아요(C49 '이의가 있으면 누구나 신고'). 법이 묻는 네 가지 공개와 같은 틀이에요(S34).
  - 신고 한 표(kind)로 A02의 '처리 기다림 · 처리함 · 전체 · 채팅 · 업체 · 링크' 거르기를 한 쿼리로 해요. 신고된 채팅 글은 신고 때 사본(`evidence`)을 남겨 보관 기간이 정해져 글이 지워져도 근거가 남아요(dev-05).
  - 업체 기능 멈추기는 업체 승인 상태와 따로 `vendors.suspended_at` · `suspend_scope`(new · all)로 둬요. 승인 심사 이력(`vendor_reviews`)과 섞지 않아요.
  - 외부 리뷰 링크(V18, 3개까지)는 `vendor_review_links`에 상태(확인 중 · 보여요 · 숨김)로 두고 관리자가 승인할 때 확인해요(A01). 고객 화면에는 '보여요'만 나가요.

## 사용자 확인 필요

- **탈퇴한 고객의 리뷰**: 지금 탈퇴는 고객 행을 지워 공사 · 확정까지 지워요. 리뷰가 함께 지워지면 업체 별점이 바뀌어요. 설계는 리뷰를 남기고 작성자 칸만 비우는 쪽(`ON DELETE SET NULL` + 지역 · 벽지 사본)으로 했어요. 법무 · 팀이 '탈퇴하면 리뷰도 지움'으로 정하면 CASCADE로 바꿔요. C53 탈퇴 창의 '사라지는 것' 목록에 리뷰를 더해야 해요(UX 글).
- 믿집이 통신판매중개자인지(팀 확인 9)는 신고 처리 기한 · 인력 규칙에 닿아요. 표는 그대로 쓰고 처리 기한 칸만 정해지면 더해요.
