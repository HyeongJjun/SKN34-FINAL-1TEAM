# data-03 에이전트 지식 조각 · 질문 은행의 형식과 저작권 처리

- 상태: 고름
- 날짜: 2026-11-18 · 쓴 역할: 데이터 수집
- 관련 화면 · 이야기: 옆 AI 칸 · 가이드 · 공종별 에이전트(무료 모드 답 카드) · 관련 파일: `data/v3/knowledge/chunks.jsonl` · `sources.csv`, `data/v3/questions/*.jsonl` · `sources.csv`, 기존 `data/consult/rag5.json`

## 배경

v3 에이전트는 공종 전체(13개)의 지식 질문에 답해야 하고, 무료 모드(검색 + 미리 만든 답 카드)가 기본이에요(지시문 1 · 3.4).

저장소에는 이미 원문을 그대로 옮긴 조각 1,432개(`rag5.json`)가 있어요. 그런데 법령 원문은 길고 어려워서 그대로 답 카드로 쓰기 어려워요. 제조사 · 블로그 자료는 라이선스가 섞여 있고요.

평가 세트의 바탕이 될 질문도 공종마다 모자라요(지금 `evaluation/trade`는 도배 9 · 목공 9문항).

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |
| A | 원문 인용 조각(`rag5`)만 계속 씀 | 원문 그대로라 정확해요 | 답 카드로 쓰기엔 길어요. 라이선스가 불명인 글은 옮기면 안 돼요 |
| **B** | **요지 조각(3~6문장, 해요체, 숫자 · 조항 번호만 원문대로) + 원문 조각 연결(`related_ref`)** | 바로 답 카드가 돼요. 원문으로 되짚을 수 있어요. 저작권 걱정이 작아요 | 요지를 쓰며 뜻이 바뀔 수 있어요 → 원문 대조 점검 |
| C | 웹 페이지 전체를 받아 임베딩 | 자료가 많아요 | 저작권 · 용량 문제, 지시문(원문 길게 옮기지 않기)과 어긋나요 |

질문 은행도 같은 원칙으로 정해요. 실제 질문을 **바꿔 쓰고** 본 곳(`source_url`)과 확인 방법(`source_check`)을 남겨요.

## 고른 것과 이유

- 고른 안: **B**
  - 조각 필수 칸: `id · trade · topic · title · summary · source_url · source_name · clause · checked_at · license`
  - 선택 칸: `effective_date · verify · related_ref · also · question_hints · doc_key`
  - `verify`는 세 가지예요: `web_opened`(이번에 본문을 직접 읽음), `version_checked`(저장소 사본 본문 + 웹에서 같은 판 · 시행일 확인), `repo_copy`(저장소 사본만).
- 라이선스 처리 규칙

| 자료 종류 | license 값 | 쓰는 법 |
| --- | --- | --- |
| 법령 · 고시 · 공고(표준품셈 · 하자판정기준 · 표준시방서 포함) | 공공저작물(저작권법 제7조, 법령 · 고시) | 조항 요지 · 숫자 · 짧은 인용 |
| 공공누리 제1유형 | 공공누리 제1유형 | 출처를 적고 요지 |
| 공공누리 제4유형(비상업 · 변경금지) | 공공누리 제4유형(요지만) | 사실 · 숫자만 다시 써요. 글을 고쳐 옮기지 않아요 |
| 라이선스를 못 찾은 글(제조사 · 언론 · 블로그) | 확인 못 함(요지만) | 일반 사실만. 블로그 · 커뮤니티는 사례 · 질문 유형으로만 쓰고 숫자 근거로 쓰지 않아요 |
| 'AI 생성' 표시가 있는 글 | — | 질문 유형 참고만. 숫자는 민감도 계산에만 넣어요(data-01) |

- 이유
  1. 지시문 3.1: 원문을 길게 옮기지 않고 사실 · 숫자 · 요지만, 보호받지 않는 공공 저작물만 조항 요지를 인용해요.
  2. 공공누리 제3 · 4유형은 변경금지예요 [근거 1]. 그래서 원문을 다듬어 옮기는 대신 사실만 새로 써요.
  3. `related_ref`로 원문 조각과 이어 두면 무료 모드는 요지 카드를 보여 주고, 근거 보기에서 원문 조각을 열 수 있어요.

## 근거 (직접 열어 확인한 것만)

- 조사: 지식 조각은 원문 페이지 65쪽(판 확인 포함)을 열었고, 질문 은행은 검색 11회 + 페이지 57쪽(WebFetch) + 아하 31쪽(WebFetch가 빈 내용을 줘서 curl로 HTML을 받아 읽음)을 봤어요. 이 턴의 검색 한도가 다 차서 질문 은행 검색은 목표 30회를 못 채웠어요.

## 검증

- 방법: `python -X utf8 data/v3/scripts/validate.py`(개수 · 빈 칸 · 중복 · 값 범위 · 문장 수 · 출처 없는 행), 조각 7개를 원문 조각과 직접 대조, 질문 12개를 표본으로 읽고 출처 1쪽을 다시 열어 봐요.
- 결과(2026-11-18 실행)
  - 조각 190개: 빈 칸 0 · id 중복 0 · 출처 없는 행 0 · 문장 수 3~6 벗어남 0 · 공종마다 6개 이상
  - 질문 493개(13개 파일 36~40개): 빈 칸 0 · 파일 사이 글자 중복 0 · 80자 초과 0 · split 규칙 어긋남 0
  - 원문 대조 7조각: 숫자 · 조항 번호 모두 맞음. `kv3-defect-006`(시트지)에는 '봉투바름 들뜸은 하자 아님' 예외가 없지만, 같은 조문을 다룬 `kv3-defect-007`(도배)에 있어요.
  - 질문 표본 12개: 원문을 옮긴 문장은 없었어요. 출처 1쪽(클리앙)은 질문 내용과 맞았어요.
