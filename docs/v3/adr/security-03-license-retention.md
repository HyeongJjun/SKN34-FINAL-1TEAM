# security-03 사업자등록증 보관 · 파기

- 상태: 제안(보관 기간은 팀 · 법무 확인)
- 날짜: 2026-11-18 · 쓴 역할: 보안 담당
- 관련 화면 · 이야기: V01 v_signup · A01 a_review · A04 a_reject · V14 v_needinfo · V22 v_rejected, J10 · J21, 9판 D26 A
- 관련 코드: `backend/app/vendor/service.py` `signup` · `_new_license` · `backend/app/files/service.py`(`license` 종류 · `readable`) · `backend/app/files/storage.py` `remove` · `backend/app/account/service.py` `withdraw` · `infra/aws/staging.yaml` FileBucket

## 배경

- 업체는 사업자등록증(JPG · PNG · PDF, 10MB)을 올려요. 관리자는 상호 · 등록번호 · 대표자를 대조해 승인 · 보완 · 거절해요(D26 A: 거절 이유 코드, 다시 신청).
- 지금 코드
  - 파일은 업체가 탈퇴할 때까지 남아요. 거절 · 보완 미응답에는 기한이 없어요.
  - 교체한 예전 파일은 지워요(`_new_license`).
  - 그런데 S3 버전 관리 때문에 지운 파일도 이전 버전으로 남아요(`security.md` F1).
- 등록증에 대표자 생년월일이나 주민등록번호가 찍히는지는 확인하지 못했어요(서식: 부가가치세법 시행규칙 별지 제7호서식, 원문 확인 필요). 찍힌다면 고유식별정보처럼 더 엄하게 다뤄야 해요.

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |

| B | 심사가 끝나면 바로 파일을 지우고 결과만 남김(확인한 날 · 관리자 · 일치한 칸 · 사업자 상태) | 가장 적게 둬요 | 신고 · 분쟁 · 다시 확인할 때 원본이 없어요. 보완 요청(V14)마다 다시 받아야 해요 |
| C | 상태별 기한: 승인 업체는 활동하는 동안(관리자만 · 열람 기록), 거절 · 보완 미응답은 30일 뒤, 탈퇴는 바로, 교체한 예전 파일은 바로, S3 이전 버전은 7일 뒤 지움 | 근거를 남기면서 기한이 분명해요 | 승인 업체 파일을 오래 둬요 |
| D | 파일 대신 국세청 진위확인 · 상태조회 API만 씀 | 파일을 아예 두지 않아요 [6] | 9판 V01(등록증 올리기)과 달라요. 새 외부 서비스(키 발급)라 따로 정해야 해요 |

## 고른 것과 이유

- 고른 안: **C**. B는 6개월 운영한 뒤 다시 봐요(승인 + 1년 뒤 파일을 지우고 결과만 남기는 안). D는 C를 돕는 선택(상태조회만 더하기)이라 ADR을 따로 써요.
- 세부
  1. 볼 수 있는 사람: 업체 본인 · 관리자만이에요(지금 `readable` 그대로).
  2. 열람 기록: 관리자가 열 때마다 누가 · 언제 · 어느 업체 · 무엇을 남겨요. 1년 이상 두고, 정보주체가 5만 명을 넘거나 고유식별정보가 있으면 2년 이상 둬요 [4].
  3. 화면 · 응답: 관리자 목록에는 파일 링크만 두고, 미리 보기는 새 창(`no-store`)이에요. 고객 화면에는 상호만 보여요.
  4. 정리 일(worker, 매일): 거절 · 보완 요청 뒤 30일 동안 다시 내지 않으면 파일을 지우고 업체에 알려요('등록증 파일을 지웠어요. 다시 신청하려면 새로 올려 주세요'). 신청 기록(상태 · 이유 코드)은 남겨요.
  5. S3: 수명 주기 규칙에 `NoncurrentVersionExpiration` 7일과 지움 표시 정리를 CloudFormation으로 더해요 [3]. 로컬 디스크는 지금처럼 바로 지워요.
  6. 올리기 안내: 주민등록번호가 찍히는 것으로 확인되면 '주민등록번호 뒷자리는 가리고 올려 주세요'를 더해요.
  7. LLM이나 외부 OCR로 보내지 않아요.
  8. 처리방침: 항목 · 목적(업체 확인) · 위 기한을 적어요 [5].
- 이유
  - 제21조: 목적을 이루면 지체 없이 파기하고, 복구 · 재생되지 않게 해야 해요 [1].
  - ASVS 14.2.7: 보유 기간이 지난 민감 정보는 일정에 따라 자동으로 지워요(14.1.1 분류와 함께) [2].
  - S3에서 버전 번호 없이 지우면 '지움 표시'만 생겨요. 영구 삭제는 버전 번호나 `NoncurrentVersionExpiration`으로 해요 [3].
  - 2025.10.31 시행 안전성 확보조치 기준은 접속기록 대상을 넓혔어요 [4].
  - 유출되면 '가능성'만 있어도 72시간 안에 알려야 해서(2026.9.11 시행), 적게 두는 것 자체가 위험을 줄여요 [7].
