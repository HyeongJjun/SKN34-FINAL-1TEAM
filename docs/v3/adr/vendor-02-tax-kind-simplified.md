# vendor-02 업체 과세 유형(일반 · 간이 · 면세)과 부가세 계산

- 상태: 사용자 확인 필요(법무 · 세무 확인도 필요)
- 날짜: 2026-11-18 · 쓴 역할: 업체 대변인
- 관련 화면 · 이야기: V15 v_profile(세금), D02 d_price('부가세 빼고'), V10 v_quote(부가세 포함 · 빼고 · 면세), V12 v_extra, C33 · D18 비교, A01 a_review · J7 · J10 · J22
- 관련 코드: `backend/app/vendor/models.py`(`tax_kind in ('general', 'exempt')`) · `backend/app/quote/models.py`(`VAT_MODES`) · `backend/app/calc/common.py`(`with_vat`) · 조사 F07 · F19

## 배경

- 9판과 지금 코드는 업체 세금을 '과세 · 면세' 둘로만 나눠요.
- 간이과세 업체가 단가표(부가세 빼고)나 실측 견적서에 '부가세 빼고'를 고르면, 믿집이 10%를 붙여 고객에게 보여 줘요.
- 대법원은 간이과세 수급인이 약정이나 관행 없이 '부가세 별도'만으로 10%를 청구할 수 없다고 봤어요. 고객이 보는 '부가세 포함 금액'이 업체가 실제로 받을 수 있는 돈보다 클 수 있어요.
- 업체 쪽에서는 가견적이 10% 비싸 보여요. 고객 쪽에서는 분쟁 거리가 돼요.

## 대안

| 안 | 내용 | 좋은 점 | 걸리는 점 |
| --- | --- | --- | --- |
| A | 그대로(과세 · 면세, 간이도 10%) | 바꿀 것이 없어요 | 판결과 어긋날 수 있어요. 간이 업체가 비싸 보이거나 '면세'를 잘못 골라요 |
| B | '간이'를 더해요. 간이 업체는 받을 돈 전부(부가세 포함)로만 받고, 공급가 · 부가세를 나누지 않아요 | 판결과 맞아요. 업체가 세율을 몰라도 돼요 | 업체가 유형을 잘못 고를 수 있어요 |
| C | B + 국세청 상태조회로 과세 유형을 채우고, 업체가 고른 값과 다르면 관리자가 확인해요. 승인 뒤에도 매달 휴 · 폐업 · 유형을 확인해요 | 잘못 고르기를 막고 휴 · 폐업도 걸러요 | 무료 외부 API · 키 관리가 늘어요 |
| D | 업체가 자기 세율(예: 3%)을 적어요 | 숫자가 정확할 수 있어요 | 업종별 부가가치율 계산을 업체에 맡겨요. 틀리기 쉽고 고객이 이해하기 어려워요 |

## 고른 것과 이유

- 고른 안: **C(제안)**. 9판 V15 · V10 칸을 바꾸므로 사용자 확인이 필요해요.
  - `tax_kind`: 일반(general) · 간이(simplified) · 면세사업자(exempt).
  - 간이 업체
    - 단가표는 '받을 금액(부가세 포함)'으로 받아요. 가견적 합계 = 단가 × 수량 합이고, 부가세 줄은 0이에요.
    - 실측 견적서 · 추가 금액은 부가세 방식 칸 없이 '받을 금액' 하나예요.
  - 고객 화면은 '합계(부가세 포함)'만 보여요. 공급가 · 부가세를 나누는 견적서 합계 칸에는 '간이과세 업체라 나누지 않아요'를 적어요.
  - 건마다 면세(국민주택 리모델링 등)는 조건이 좁아요. 세무 확인 전에는 9판 V10 '면세'를 관리자 확인 대상으로 둬요.
  - 국세청 상태조회
    - 가입(V01) · 심사(A01) 때, 그리고 승인 뒤 매달 1번 해요.
    - 다르면 A01에 '국세청 과세 유형과 달라요'를 보이고 업체에 알려요.
    - 휴 · 폐업이면 관리자 확인으로 넘겨요(자동 정지는 하지 않아요).
  - API 키는 서버 설정에만 두고, 대표자명은 진위확인에만 써요.
- 이유
  - 간이과세 수급인은 약정 · 관행이 없으면 납부세액 상당액만 청구할 수 있어요[1]. 인테리어 사례에서는 3%였어요[2].
  - 국세청 상태조회는 무료이고 과세 유형 · 휴 · 폐업을 줘요[3]. 숨고도 공공 API로 자격을 자동 검증하고 휴 · 폐업을 바로 반영하겠다고 했어요[4].
  - 지금 코드와 9판에는 간이가 없어요[5][6].
  - D는 업체가 법령 계산(업종별 부가가치율)을 해야 해서 틀리기 쉬워요[1].
- 지키는 규칙: '고객이 보는 금액은 부가세 포함'은 그대로예요. 간이는 나눠 보일 부가세가 없어서 합계만 보여요.

## 검증

- 방법
  1. 계산 엔진 단위 테스트(세 유형)
     - 일반: 공급가 + 10%
     - 간이: 합계 = 받을 금액, 부가세 0, 나눔 표시 없음
     - 면세: 0
  2. 국세청 API: 사용자가 키 발급에 동의하면 무료 키로 로컬에서 응답 모양만 확인해요(유료 아님). 키는 문서 · 커밋에 남기지 않아요.
  3. 법무 · 세무 질의 1번: 간이 업체 견적 표시 문구, 건마다 면세 조건.
- 결과: 검증 대기

## 다시 볼 조건

- 부가가치세법 개정(간이과세 기준 금액 · 부가가치율)
- 믿집이 결제 · 세금계산서를 맡게 될 때
- 법무 · 세무 의견이 다를 때
- 간이 업체 비율이 매우 낮다고 확인될 때(B로 줄이기)
