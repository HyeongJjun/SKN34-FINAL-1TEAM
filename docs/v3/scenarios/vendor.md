# 업체 페르소나 · 업체 시나리오 스크립트 (9판 기준)

- 쓴 날: 2026-11-18 · 쓴 역할: 업체 대변인 · 기준: `docs/v3/00-prompt.md`, 9판 설계 `docs/v3/design/`
- 목적: 실제 화면이 생긴 뒤 업체 대변인이 앱 안 브라우저로 폰 · 웹 둘 다 끝까지 해 봐요. 결과는 `docs/v3/verification/scenario-vendor.md`에 남겨요.
- 번호: 근거 `S` · `T`, 점검 `F`는 `docs/v3/research/vendor.md` 번호예요. ADR은 `adr/vendor-01~03`이에요.

## 0. 돌리기 전 준비

- 실행: `LLM_LIVE=false`, `OPENAI_API_KEY` · `ANTHROPIC_API_KEY`는 비워요. 개발 DB `mitjip_v3`, 테스트 DB `mitjip_test_vendor`예요.
- 계정: `seed.py` · `demo.py`가 만드는 시연 고객 · 업체 · 관리자 계정을 써요. 비밀번호는 `.env`의 `SEED_PASSWORD`라 문서에 적지 않아요.
- 화면 크기: 폰 360×800, 웹 1280×800이에요(앱 안 브라우저 크기 바꾸기). 끝나면 크기를 되돌려요.
- 시간
  - 기한(48시간 · 7일 · 실측 + 3일 · 확정 + 2일)은 서버 시계를 바꾸지 않아요. 개발용 '기한 일 바로 돌리기' 명령으로 확인해요(개발자에게 요청함).
  - 명령이 없으면 그 칸은 '확인 못 함'으로 적어요.
- 공통 확인(모든 시나리오)

  | 확인 | 기준 |
  | --- | --- |
  | 가로 스크롤 | 폰 360px에서 없어요 |
  | 누를 곳 | 44px 이상(최소 40px) |
  | 글 | 해요체, 영어 상태값 없음, 'VAT' 대신 '부가세' |
  | 금액 | 고객에게는 부가세 포함, 나눠 보이는 곳은 견적서 합계 칸 하나 |
  | 위치 | 업체 화면에는 동까지만(동 · 호 · 연락처는 고객이 채팅에 직접) |
  | 권한 | 남의 요청 · 공사는 404, 고객 계정으로 `/vendor`는 403 |
  | 같은 요청 두 번 | 단추 두 번 · 두 탭 동시 → 한 번만 저장되거나 409 |
  | 파일 | PDF · 엑셀 · 사진만, 크기 한도, 사진은 '위치 정보 지움' |

- 기록 칸: 날짜 · 시나리오 · 기기 · 결과(통과 · 실패 · 막힘) · 걸린 시간 · 누른 횟수 · 메모.

## 1. 업체 페르소나

### P1 이○○ 사장 — 도배 1인 + 조공, 폰 하나로 일해요 (9판 예시 업체 '마루와벽')

| 항목 | 내용 | 근거 |
| --- | --- | --- |
| 사람 | 50대 초(가정), 도배 15년 넘음, 노원 · 도봉 · 중랑 · 성북 | 9판 V15 '도배만 12년' |
| 인원 | 혼자 + 큰 집이면 조공 1명(2인 1조) | S23 · T2 '최소 2인' |
| 기기 · 연락 | 폰 하나. 전화가 편하고 문자로 사진을 주고받아요. PC는 거의 안 써요 | S24(전화 상담 부탁) |
| 하루 | 08~12시 철거 · 초배, 13~18시 정배, 저녁에 실측 · 견적 | S26 · S27 |
| 일정 | 월 단위로 공사를 받아요('12월 일정 받아요') | S23 · S25 |
| 견적 | 벽지 롤 + 인건비(인원 × 일당 27~28만) + 부자재, 사는 집은 더 받아요 | S24 · S23 · T1 |
| 세금 · 등록 | 간이과세(가정), 실내건축공사업 등록 없음(1,500만 원 미만 도배라 의무 없음) | S1 · S3 |
| 플랫폼 경험 | 숨고 견적비가 아까웠어요. 당근 프로필은 있어요 | S17 · S23 |
| 원하는 것 | 헛걸음 없는 요청(공사 날 · 벽 상태), 폰에서 1~2분 안 답, 바쁠 때 요청 끄기, 비싸 보이지 않는 가견적 | 2.3 '업체가 원하는 것' |
| 걱정 | 알림을 놓쳐 '답 없음', 단가표 단위, '확인 안 됨' 표시, 10% 붙어 비싸 보임 | F12 · F02 · F08 · F07 |

### P2 김○○ 실장 — 부부 2인 도배팀의 사무 담당 (9판 예시 업체 '결도배')

| 항목 | 내용 | 근거 |
| --- | --- | --- |
| 사람 | 40대(가정), 낮에는 현장 조공, 밤에 PC로 사무를 봐요 | S23(부부 도배사) |
| 기기 | 낮에는 폰, 밤에는 PC(엑셀 견적서 · 블로그 · 당근 프로필) | S29(업체용 견적 · 일정 앱) |
| 하는 일 | 단가 정리, 여러 요청 한 번에 답하기, 견적서 파일 올리기, 리뷰 답글 | S23 · S24(사장님 답글) |
| 세금 | 일반과세 | (가정) |
| 단가 습관 | 합지는 안 받아요(9판 결도배 '빼기'). 실크 롤값 · 일당으로 셈해요 | 9판 D02 · T1 |
| 원하는 것 | 데스크톱 표로 걸러 보기, 같은 기간을 여러 집에, 사장과 같은 계정을 나눠 쓰기 | F10 · F30 |
| 걱정 | 같은 반나절을 두 고객이 고름, 리뷰가 부당할 때 알릴 곳이 없음 | ADR vendor-03 · F17 |

| 항목 | 내용 | 근거 |

## 3. 시나리오 스크립트

### VS01 가입 신청 → 보완 요청 → 다시 보내기 → 승인

- 사람 · 기기: P1 폰 360 + 관리자 웹 1280
- 시작 상태: 로그아웃. 고객 홈 C01 바닥의 '업체로 가입'에서 시작해요.
- 단계
  1. C01 '업체로 가입' → V01. 상호 '마루와벽' · 대표자 · 등록번호 · 이메일 · 공정 '도배' · 지역(노원구 · 도봉구)을 넣어요. 일부러 흐린 등록증 사진을 올리고 '가입 신청'을 눌러요.
  2. (관리자) A01에서 '마루와벽'을 열고 '보완 요청'(사진이 흐려요)을 눌러요.
  3. (업체) V21 알림 → V14. 새 사진을 올리고 '다시 보내기'를 눌러요.
  4. (관리자) A01에서 상호 · 번호 · 대표자가 같은지 보고 외부 리뷰 링크를 연 뒤 '승인'을 눌러요.
  5. (업체) V02 '승인됐어요'와 처음 할 일 4개를 봐요.
- 기대 결과
  - 상태가 심사 기다림 → 보완 요청 → 심사 기다림 → 승인으로 바뀌어요.
  - V14 심사 기록이 2줄이고, 승인 알림은 1번 와요.
- 확인할 위험
  - [ ] 비밀번호를 어디서 넣는지(9판 '다음 칸에서' · 작은 고침 S10 보류 — 실제 화면 그대로 적어요)
  - [ ] 등록증에 '위치 정보 지움'이 보이고 실제로 지워졌는지(파일 내려받아 확인)
  - [ ] 언제 결과가 오는지 안내가 있는지(F20)
  - [ ] A01에 국세청 확인 줄이 없어 눈으로만 견주는지(F19 · ADR vendor-02, 9판 그대로면 '없음' 기록)
  - [ ] PDF · 사진 밖 파일과 큰 파일이 막히는지, '다시 보내기' 두 번이 한 번만 되는지
- 변형: P3로 '목공'만 골라 가입하고, 승인 뒤 할 일이 있는지 봐요(작은 고침 S09 보류 메모).

### VS02 거절 → 이유 보고 다시 신청

- 사람 · 기기: 관리자 웹 1280 → P1 폰 360
- 시작 상태: '마루와벽'이 심사 기다림이에요. 신청 번호를 등록증과 다르게 넣어 뒀어요.
- 단계
  1. (관리자) A01 '거절' → A04. 이유 '사업자등록증과 신청 정보가 달라요'를 고르고, 메모를 적고 '거절하기'를 눌러요.
  2. (업체) V22에서 이유 · 메모를 봐요. '신청 정보 고치기' → V01에서 번호를 고치고 '다시 신청'을 눌러요.
  3. (관리자) A01 목록에 새 신청이 '심사 기다림'으로 와요.
- 기대 결과: V22에 이유 글이 그대로 보여요. 다시 신청하면 처음부터 심사하고 기록이 남아요.
- 확인할 위험
  - [ ] 이유 글만 보고 무엇을 고칠지 알 수 있는지
  - [ ] 다시 신청할 때 이미 넣은 값 · 파일이 남는지
  - [ ] 거절된 업체가 업체 기능(`/vendor/prices/dobae` 등)에서 403인지

### VS03 단가표 처음 넣기와 고객 화면 확인 (ADR vendor-01 · 02)

- 사람 · 기기: P2 웹 1280 → 같은 화면 폰 360 → 고객 계정 폰
- 시작 상태
  - '결도배'는 승인됐고 단가가 없어요. 고객 목록에는 '가견적 준비 중'(D06 A)이에요.
  - 결도배에 이미 실측을 요청한 고객 1명을 미리 만들어 둬요(값 고정 확인용).
- 단계
  1. V02 '도배 단가 넣기' → D02. 평소 말대로 넣어요.
     - 실크: '롤 4만 5천 원'을 그대로 넣어 봐요.
     - 인건비 28만, 부자재, 식대 '인건비에 포함', 퍼티 평당 1만 5천.
     - 합지는 '빼기', 운송비는 비워요.
  2. 인건비에 일부러 2,800,000을 넣어 10배 경고를 보고 고쳐요.
  3. 운송비 빈 칸에서 '단가를 넣어 주세요'를 보고 '다른 줄에 포함'을 골라요.
  4. '확인하고 저장'을 눌러요. 두 탭에서 거의 같이 저장도 해 봐요(D29).
  5. 같은 화면을 폰 360으로 열어요(F01).
  6. (고객, 상계동 69.4㎡ 실크) C10 · C11에서 가견적 · 줄 · '표준보다 N%'를 봐요.
  7. (고객, 합지 집) C10에서 결도배가 '이 벽지는 안 해요'이고 담기가 막히는지 봐요.
  8. 미리 요청한 고객의 고정 가견적이 그대로인지 봐요.
- 기대 결과
  - 저장 전에 경고 · 빈 칸 막기가 돼요. 저장하면 고객에게 바로 보여요.
  - 이미 요청한 고객 값은 그대로예요. 두 번째 저장은 409예요.
- 확인할 위험
  - [ ] 롤값을 '평당' 칸에 넣었을 때 금액이 5배로 커지는지(F02 — 9판 A안 그대로면 '업체 실수 가능'으로 기록)
  - [ ] 퍼티가 늘 합계에 들어가는지(F03)
  - [ ] 시장 범위 단가(T1: 실크 공급가 평당 6.9~9.8만)로 넣어도 '표준보다 N% 많아요'가 크게 나오는지(F04)
  - [ ] '부가세 빼고' 안내가 간이과세 업체에 맞는지(ADR vendor-02)
  - [ ] 폰에 단가 화면이 있는지, 줄마다 '이 집이면' 금액이 보이는지(F01)
  - [ ] 품 수량 근거(N품)가 보이는지, 합지 집에서 품이 실크와 같은지(F05)

### VS04 새 실측 요청에 48시간 안에 기간 답하기 (바로 확정 켬)

- 사람 · 기기: P1 폰 360 + 고객 폰
- 시작 상태: 고객(상계동 69.4㎡ · 빈 집 · 실크 · 희망 12.7~12.21 · 공사 시작 1.4)이 11.17 21:40에 마루와벽 · 결도배에 요청했어요(C13). 사진 2장이 있어요.
- 단계
  1. (업체) 다음 날 아침 폰을 열어 새 요청을 알아차려요(V21 또는 첫 화면 배지).
  2. V03 '새 실측 요청' 카드에서 동네 · 면적 · 가견적 · 예산 · '내일 21:40까지'를 봐요.
  3. V04에서 12.13~12.18을 고르고 16일을 빼요. '고객이 고르면 바로 확정'을 켜고 '보내기'를 눌러요.
  4. (고객) C14 '날짜 고를 차례' → C16 12.15 오전 → C61 확인 → C17.
  5. (업체) V21 '실측이 정해졌어요', V08에 12.15 오전, V19에 새 대화가 생겨요.
- 기대 결과
  - 첫 답 기한은 보낸 때 + 48시간, 고객 고르기 기한은 업체 답 + 7일이에요.
  - 바로 확정으로 잡힌 반나절은 다른 요청 기간에서 빠져요. 채팅이 열리고, 전날 18:00 알림이 양쪽에 1번씩 가요.
  - 목표: 알림에서 '보내기'까지 2분 안, 누름 10번 안.
- 확인할 위험
  - [ ] 알림을 못 본 업체가 할 일을 어떻게 아는지(첫 화면 '할 일 N' · 배지, F12)
  - [ ] 공사 시작 희망일(1.4)이 카드 · V04에 보이는지(F09 — 9판 그대로면 '안 보임' 기록)
  - [ ] 믿집 밖 공사 날을 요청마다 다시 빼야 하는지(F10)
  - [ ] 한 반나절에 실측 1건만 되는지(ADR vendor-03)
  - [ ] 사진 크게 보기 · 위치 정보 지움, 동까지만 보이는지

### VS05 못 받아요

- 사람 · 기기: P1 폰 360 + 고객 폰
- 시작 상태: 새 실측 요청 1건(VS04와 같은 고객 · 다른 업체 칸)이 있어요.
- 단계
  1. V03 → V04 → '못 받아요' → V05에서 '일정이 꽉 찼어요'를 고르고 '보내기'를 눌러요.
  2. (고객) C14 · C18에서 그 업체 칸이 비고 다른 업체를 담을 수 있는지 봐요.
- 기대 결과: 고객 알림 1번, 업체 작업함에서 그 요청이 '끝남'으로 가고 기록이 남아요.
- 확인할 위험
  - [ ] 이유 3가지로 충분한지(예산 · 범위 이유는 작은 고침 S09 보류 메모)
  - [ ] 잘못 눌렀을 때 확인 창 문구가 분명한지(되돌리기 없음)
  - [ ] 다니는 지역 밖 요청이 얼마나 오는지(F26)

### VS06 여러 집에 같은 기간 · 같은 반나절을 동시에 (ADR vendor-03)

- 사람 · 기기: P2 웹 1280 + 고객 A · B(두 브라우저 탭)
- 시작 상태: 결도배에 요청 2건(상계동 · 공릉동)이 있고, 둘 다 '바로 확정'을 켰어요.
- 단계
  1. D04 표를 '기한 가까운 순'으로 보고, 줄을 눌러 오른쪽 자세히를 봐요.
  2. D14에서 두 요청 모두 12.13~12.18로 답하고 '고객이 고를 수 있는 반나절 N칸'을 봐요.
  3. 고객 A · B가 같은 12.15 오후를 거의 같이 '이 날짜로 확정'해요.
  4. (업체) D14 '이미 잡힌 실측' · V08에서 결과를 봐요.
- 기대 결과
  - 한 명만 확정되고, 늦은 쪽은 '방금 다른 고객이 골랐어요'(409)예요.
  - 잡힌 반나절은 회색이고, 위 숫자(할 일 · 기다림 · 일정)와 줄이 맞아요.
- 확인할 위험
  - [ ] 수용량 1이라 업체가 하루 2건만 받는지(ADR vendor-03, 9판 그대로면 기록만)
  - [ ] 같은 '빼는 날'을 두 요청에 두 번 넣어야 하는지(F10)
  - [ ] 1280에서 표가 넘치지 않고 '다음 일'이 한 줄로 끝나는지(N4 C)

### VS07 바로 확정 끔 → 수락 · 다른 날 제안

- 사람 · 기기: P1 폰 360 + 고객 폰
- 시작 상태: 결도배는 '바로 확정'을 껐어요. 고객이 12.16(수) 오전을 보냈어요(C19).
- 단계
  1. V21 '고객이 날짜를 골랐어요' → V06에서 기한 · '잡아 둠'을 봐요.
  2. '다른 날 제안' → V07에서 이유 '다른 현장이 있어요'와 반나절 2개(12.16 오후 · 12.17 오전)를 고르고 보내요.
  3. (고객) C20 → C21 12.16 오후 → 확정.
  4. (업체) V08 · V19에서 일정과 새 대화를 봐요.
- 기대 결과: 잡아 둔 반나절은 48시간 동안 다른 고객에게 막혀요. 제안 기한도 48시간이고, 확정 뒤 채팅이 열려요.
- 확인할 위험
  - [ ] 희망 기간(12.7~12.21) 밖 날은 제안할 수 없는지, 그때 업체가 할 수 있는 일
  - [ ] 제안 3개 제한, '수락' 두 번 → 한 번만
  - [ ] 기한이 지난 뒤 화면(D12 보류 — 보이는 대로 기록만)

### VS08 실측 당일 → 실측 견적서 올리기 → 고객 비교 · 확정 (ADR vendor-02)

- 사람 · 기기: P1 폰 360 + 고객 웹 1280
- 시작 상태: 12.15(화) 오전 상계동 실측이 확정됐어요.
- 단계
  1. 12.14 18:00 V21 '내일 오전 실측이에요'를 봐요.
  2. V09에서 고객이 보낸 동 · 호 · 연락처를 보고 전화를 걸어 봐요(F22).
  3. (실측 뒤, 고객) C32 '실측 받았어요'를 눌러요.
  4. V10에서 손글씨 견적서 사진을 올려요. 4칸을 넣어요(낼 금액 2,970,000 · 부가세 '빼고' · 공사 2일 · 유효기간 12.31). 칩 4개 · 제조사 · 하자 1년도 넣어요. '임시 저장' 뒤 '고객에게 보내기'를 눌러요.
  5. (고객, 웹) D18 비교 → C34 확정.
  6. (업체) V21 '견적서가 확정됐어요 · 공사 날짜를 올려 주세요'를 봐요.
- 기대 결과
  - 믿집 계산이 '공급가 + 부가세 = 합계'예요. 기한은 실측 + 3일 18:00이에요.
  - 다시 올리면 버전이 쌓이고, 확정한 버전은 바뀌지 않아요. 다른 업체 견적서는 닫혀요.
- 확인할 위험
  - [ ] 간이과세 업체가 '빼고'를 고르면 합계가 얼마인지(ADR vendor-02)
  - [ ] 폰에서 걸린 시간 · 누름 횟수(F24)
  - [ ] 엑셀 · PDF · 사진이 다 되는지, 크기 한도, 사진 위치 정보
  - [ ] 임시 저장만 해 둔 견적서가 기한 전에 할 일로 다시 보이는지
  - [ ] 채팅에 남은 주소 · 번호가 언제까지 보이는지(F27)
  - [ ] 업체 화면에서 번호를 눌러 바로 전화되는지(F22)

### VS09 공사 날짜 → 공사 한 건 → 추가 금액 → 공사 끝

- 사람 · 기기: P1 폰 360 + 고객 폰
- 시작 상태: 12.17 마루와벽이 확정됐어요(326만 7,000원 · 공사 2일).
- 단계
  1. V11에서 1.4(월) · 1.5(화)를 고르고(1.1 신정은 회색), 인원 2명으로 보내요.
  2. (고객) C52 '다른 날짜 요청' 1번 → (업체) V11에서 다시 보내요 → (고객) C35 수락 → C36 확정 공정표.
  3. 1.4 08:30 V03 '공사' 탭 → V23 '공사 한 건'.
  4. V12에서 '곰팡이 방지 처리 · 50,000원 · 부가세 빼고 · 사진 1장'을 보내요. (고객) C37 승인.
  5. V13에서 끝낸 날 1.5 · 사진 3장 · 남길 말을 넣고 '고객에게 알리기'. (고객) C38 확인 → C39 리뷰.
- 기대 결과
  - 고른 날 수가 공사 기간과 같아야 보내져요. 공휴일 · 겹침은 계산 엔진이 확인해요.
  - 추가 금액은 승인 전 합계 밖이고, 승인 뒤 332만 2,000원이에요.
  - 공사 끝은 7일 뒤 자동으로 끝나고, 3일 전에 알려요. V23 기록 줄이 쌓여요.
- 확인할 위험
  - [ ] 고객이 추가 금액에 답하지 않으면 현장이 어떻게 되는지(F16)
  - [ ] 업체가 공사 날짜를 내 캘린더에 넣을 길이 있는지(F23)
  - [ ] 다른 날짜 요청 2번 제한, 공사 날짜 기한 '확정 + 2일 18:00'
  - [ ] 추가 금액 같은 요청 두 번 → 한 번만(D29)

### VS10 일정 바꾸기 요청 · 알림 · 리뷰 답글

- 사람 · 기기: P2 폰 360 + 고객 폰
- 시작 상태: 12.15(화) 오전 실측이 확정됐어요. 끝난 공사 1건과 리뷰 1건이 있어요.
- 단계
  1. (고객) C28 '12.15 오전 → 12.17 오전' 요청을 보내요.
  2. (업체) V21 → V20에서 '받기'를 눌러요(변형: '다른 날 제안'). V08에 반영됐는지 봐요.
  3. V24 '답글 기다림 1' → V25 답글 → (고객) C48에 보이는지 봐요 → 답글을 고쳐요.
  4. 기준에 안 맞는 리뷰(예: 개인정보가 든 글)를 알리려고 해 봐요.
- 기대 결과
  - 받기 전까지는 원래 일정 그대로예요. 받은 뒤 양쪽 일정이 바뀌고 알림은 1번씩 가요.
  - 답글은 리뷰마다 하나예요. 고칠 수 있고, 고객에게 알림이 가요.
- 확인할 위험
  - [ ] 48시간 안에 답하지 않으면 원래 일정이 그대로인지
  - [ ] 리뷰를 알릴 길(F17 — 9판 그대로면 '없음'으로 기록)
  - [ ] 알림 목록에서 지난 알림을 찾기 쉬운지

## 4. 결과 적는 법

- `docs/v3/verification/scenario-vendor.md`에 시나리오마다 한 줄씩 적어요(날짜 · 기기 · 결과 · 걸린 시간 · 누름 횟수).
- 막힌 곳은 따로 표로 적어요(화면 · 무엇 · 다시 하는 법).
- 9판 결정대로 동작한 것과 업체 부담(F · ADR)을 나눠 적어요. 9판 그대로라 생기는 부담은 '실패'가 아니라 '업체 부담 · 사용자 확인 필요'로 적어요.
- 실패는 실패로 적고, 테스트를 건너뛰지 않아요.
